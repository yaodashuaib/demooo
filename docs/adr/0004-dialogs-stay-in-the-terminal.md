# 对话确认留在终端，不上设备

D50 只承接「权限裁决」——决定一个工具动作执不执行。像 `AskUserQuestion`、`ExitPlanMode` 这类对话工具，虽然同样会触发 `PermissionRequest`，但它们的产物是一个问题，设备按下「同意」只等于允许提问，随后屏幕还要人从多个选项里挑一个，设备既显示不了选项也回填不了答案。所以 `d50-hook` 在工具名层面直接放行，一个字节都不发往设备。

## Status

accepted

## Considered Options

- **设备上渲染选项**：把 `questions[].options` 投影成最多 4 个按钮，再由 hook 把选择回填成工具结果。可行的方向，但要先摸清 `PreToolUse` 的结果回填语义，复杂度比权限门控高一个量级。
- **只在设备上提示、答案仍在终端**：纯镜像。用户会以为按了没反应，比不做更糟。
- **不做**（本决定）：成本为零，行为可预期。

## Consequences

- 设备上永远不会出现「按了同意但 Agent 没动静」的对话确认——那正是 2026-10-29 第一次联调时最容易被当成 bug 的形态。
- 常量 `DIALOG_TOOLS` 是唯一的开关点；将来真要接管，改这里而不是改服务。
- 代价：如果以后想把「选一个」也搬到设备上，需要另起一条链路（`PreToolUse` + `updatedInput`/工具结果回填），不能复用现在的 `PermissionRequest` 通道。
